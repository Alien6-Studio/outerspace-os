02 / TWO WORKER PROFILES

Choose the host
for your workload.

The same immutable Core, with a profile for the job your worker needs to do.

  • AGENTGive each task a boundary.

    Run small containerized tools and jobs with restricted permissions, fixed resource budgets and operator-controlled network access.

    One container per task, up to 1 CPU and 256 MiB RAM. Temporary workspace. Shared-kernel execution.

  • INFERENCEBring your model to the cluster.

    Host your CPU serving engine and model weights as Kubernetes workloads. Replace the application, drain the node and recover after a restart.

    Exercised with llama.cpp. Your serving engine and weights are deployed separately.

03 / A FOCUSED HOST

Keep the system predictable.

01

A read-only foundation

The OS stays separate from your application dependencies. dm-verity detects system filesystem corruption; tools and libraries travel with their containers.

02

State that survives restart

Container storage, logs and the worker's enrolled identity live in persistent node state. A reboot does not require the original bootstrap credentials.

03

Network access you control

Use Cilium for cluster networking and policy. Agent tasks start with default-deny access; your operator decides which connections to allow.
