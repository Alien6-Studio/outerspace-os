## Changes and focused verification

CPU serving separates bounded OCI/model delivery from token-producing readiness.
It retains Pod/Deployment diagnostics and requires the current rollout and actual
runtime controls. Cold-node recovery confirms a new boot, waits through the exact
previous container's stale status, then requires the same Pod, a new container and
exactly one restart. New-container crashes, OOMs and failed model verification
remain fatal.

The [focused recovery archive](https://github.com/Alien6-Studio/outerspace-os/tree/a18c741a32dcc43eb694cef341a300df3626a462/evidence/serving-recovery-20261029)
retains 46 requests, 368 generated tokens, all five serving phases, nine admission
refusals and two real model refusals on the OuterSpace worker. It includes the
observed old-to-new container transition, eight startup waits, raw logs,
recomputed summaries and 28 source-input hashes. The harness is
`3aae7a5509bd83835143eb2421aef4ec9ffe5219`; the immutable Inference image source is
`c80dc98d492b4cd228b20ca8d0602427fa2977b6`, with raw disk SHA256
`d37e550741e85d65a3b72d402fd9762391743be2973ac6ccbdd7b62579c9678b`.

The enclosing comparison subsequently timed out waiting for the Ubuntu worker.
It exited with code 2; this archive is a passing **OuterSpace-only** regression

lifetime, exceeding the six-hour job budget. The harness still owns cleanup.
The targeted regression checks the actual generated commands for all three
fixtures against the configured job budget.

The final local `make check` passes 163 tests and shell syntax checks. No additional
complete Agent or native Inference campaign was launched for the lifetime fix.
