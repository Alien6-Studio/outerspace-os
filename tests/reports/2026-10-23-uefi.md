# Full-disk UEFI and persistence validation — 2026-10-23

Development working-tree validation on arm64, before commit-bound CI qualification.
This is not a release attestation, bare-metal result or agent-runtime qualification.

## Passed locally

- 38 contract/regression tests and shell syntax checks.
- Native arm64 image build from Ubuntu Noble packages.
- Two QEMU TCG cold starts through AAVMF, the disk ESP's systemd-boot and on-disk
  UKI, with no external kernel/initrd or command-line replacement.
- Both boots: verity root read-only, writable `/var`, cgroup v2, bpffs/BTF,
  AppArmor availability, hardening sysctls, locked operator account and CRI API.
- First boot writes a random nonce and records hostname, machine ID and boot ID.
  After clean shutdown, the same disposable disk overlay and firmware state are
  restarted. Nonce and hostname persist, machine ID remains stable and boot ID
  changes. The original raw image's SHA256 remains unchanged.

The machine ID is derived from the fixed QEMU VM UUID. Physical-host machine-ID
persistence and rotated kubelet identity persistence remain unqualified.

## Defects exposed and corrected

The earlier split-kernel smoke test did not exercise the EFI chain. Full-disk
testing found a 4096-byte FAT sector size in a 512-byte GPT disk, and an ARM64
gzip kernel payload that the EFI stub could not load. Set `SectorSize=512`,
normalize both Ubuntu kernel copies before UKI assembly, preserve input/prepared
hashes and keep only EFI boot assets in the ESP. Reading firmware variables also
needs a stream because efivarfs does not support seeking.

## Observations and limits

In this single empty-worker VM with two virtual CPUs and 1536 MiB configured RAM,
`free -m` reported 179 MiB used on the first boot and 167 MiB on the second.
Root ext4 reported 614 MiB used; the raw disk's apparent size includes a 2 GiB
state partition. These are lab observations, not product footprint guarantees.

Secure Boot was disabled. No Kubernetes enrollment, CPU inference, GPU, physical
hardware, abrupt power-loss recovery, agent isolation or CIS audit was tested.
The beta `state_reboot` gate still requires a real enrolled worker's state and
rotated identity to survive reboot.

Reproduce with `make check builder build smoke`. Logs are
`build/boot-uefi-prepare.log`, `build/boot-uefi-verify.log` and the combined
`build/boot-smoke.log`; `build/uefi-smoke.json` binds success to the raw image hash.
Packaging requires this evidence. CI repeats the full build and test on native
amd64 and arm64 runners and binds packaged output to its source commit.
